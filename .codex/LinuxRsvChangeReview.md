## 結論

A-1 の主要な判定ロジックに、計画からの移植漏れや今回のオフライン検証で再現する不具合は見つからなかった。変更後設定、固有／共通マージン、負マージン補正、64 bit 演算、厳密な境界、保護対象を変更対象に残す処理は実装されている。

ただし、計画の第7節をすべて実行したわけではない。実サーバーの通信・Lua 入口から予約ファイル保存・再生成・録画までを通す検証と Windows ビルドは未実施。**「本番動作まで検証完了」ではない。**

## 今回の修正

1. `EpgTimerSrvMain.cpp` の負マージン補正コメントが、補正方向と逆の説明だったため修正した。判定式は変更していない。
2. `EpgTimerSrvSetting.cpp` の新しい厳密整数パーサーと必要な標準ヘッダーを非 Windows ビルドに限定した。Windows に不要な未使用関数を持ち込まないための修正であり、Windows で実際にビルド失敗したという意味ではない。
3. 真偽値の整数読み込みの下限を `INT_MIN` にし、計画どおり符号付き整数を受理するようにした。従来の Luna 実装でも負値は既定値 true になっていたため、外部から見える真偽値は変わらない。
4. 既存3ソースファイルの混在改行を元の CRLF にそろえた。
5. [再実行可能な回帰テスト](../tests/linux_rsv_change/README.md)を追加した。テストを本体の式とは別の模倣実装だけで済ませない構成とした。

WebUI、配置済み設定、本番の予約データは変更していない。

## 設定と運用上の注意

Linux の `EpgTimerSrv.ini` の `[SET]` で `CautionOnRecChange`（既定1）と `CautionOnRecMarginMin`（既定5）を読む。未設定でも従来の固定1分から5分に変わる。`CautionOnRecChange=0` は保護なしではなく1分、保護設定有効時の分数0は現在時刻を境界とする。既存の連動フラグの既定値は変更していない。

T17 は Windows 互換の限界として残る。番組開始12:00、現在11:54:30、開始マージン600秒から0秒への変更、保護5分の場合、変更後の開始時刻が期限より先なので削除可能となる。**変更前に録画中なら必ず保護される、という修正ではない。** 今回この仕様を無断で変更していない。

11:00 前の予約を保護するため、`sudo make install`、`sudo systemctl restart edcb`、本番への予約変更要求は一切実行していない。インストール／再起動は本レビューに必要なかったため、11:00以降の自動実行も予約していない。

後続で実サーバーの経路検証を行う場合も、優先するのは設定・予約・ポート・保存先・チューナーを隔離した環境である。11:00を過ぎたことだけを理由に、本番予約を使う破壊的テストは行わない。本番反映をする場合は、その時点の録画・次の予約を確認したうえで別途実施する。
