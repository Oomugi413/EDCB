# Linux A-1 オフライン回帰テスト

リポジトリのルートから実行する。Python 3、g++、Linux 開発環境が必要。

```sh
python3 tests/linux_rsv_change/run.py --mutations
```

本番サービスの起動・停止、インストール、配置済み INI の書き換えは行わない。生成ソース、バイナリ、INI は `tempfile.TemporaryDirectory` の中だけに作成する。

## 本物の実装を使う範囲

- 現在の `EpgTimerSrvMain.cpp` から `AUTO_ADD_SYNC_WORK_ITEM` と同期用ヘルパー群、`SyncChangeAutoAddReserveData()` 全体を変更せず抽出して C++ としてコンパイルする。時刻式をテスト側に書き写さない。
- `EpgTimerSrvSetting.cpp`、`Common/PathUtil.cpp`、`StringUtil.cpp`、`TimeUtil.cpp` を直接コンパイル・リンクする。実際の `LoadSetting()` に一時 INI を読ませる。
- 予約・ルールの構造体、無効モード判定、時刻変換、予約との対応付け、他ルール保護、削除／変更への振り分けは本体の実装。
- `-DNDEBUG` 下でも動く明示的な合否判定と UBSan を使用する。

## テスト用に置き換える範囲

- サーバー本体のクラスは必要なフィールドだけを持つホストに置き換える。実サーバーのコンストラクター・メインループは呼ばない。
- 現在時刻を固定し、ルールはメモリー内に保持する。
- EPG 検索は用意した番組を返す。キーワード検索エンジン自体は検証しない。
- 予約管理は変更・削除要求を記録するだけ。`PreChgReserveData()` は恒等処理、デバッグログは無出力。予約ファイル保存、チューナー、録画継続性は検証しない。

## カバレッジと限界

`.codex/LinuxRsvChangePlan.md` の T01–T20、100 ns の境界前後、極端な整数値、INI の有効値・不正値・反復読み込みを検証する。EPG／プログラムの双方で I01–I11 と I13 の代表ケースを通す。I10 はチューナー変更時も変更前ルールで対応付くことを対象とし、固定チューナー条件の全組合せではない。

`--mutations` は一時生成ソースだけに、固定60秒・変更前予約・共通マージン無視・負値補正欠落・比較境界・保護対象消失の6種類の誤りを個別に入れ、テストの失敗を確認する。コンパイル失敗や sanitizer の異常終了を「検出成功」に数えない。最後に無変更の本体で再実行する。

実際の Lua／通信コマンドの入口、`ReloadSetting()` 呼び出し経路、I12 の一般削除、I14 の新規予約生成はこのハーネスでは実行しない。サーバー全体のビルドは別途行う。ハーネス成功を実機検証完了とみなさない。
